# T0: Product Foundation & Architecture

Owner expertise: Architecture. No individual assignment implied.

## Research question

Evaluate Excalidraw licensing, controlled editing hooks, Discord iframe constraints and GoDaddy VPS feasibility using versioned primary evidence.

## Required contract

Specify system boundaries, trust zones, command and event ownership, consistency invariants and ADR review process.

## Capability scope

### Product contract

- **Requirements and use cases**: Define moderator-led workshops, viewer participation, guild-owned boards and abuse cases; distinguish MVP from v1.0; record measurable availability, latency, capacity and recovery objectives without claiming measurements.

- **Interaction and system architecture**: Map Activity, API, bot, collaboration, database and assets; diagram data flows and trust boundaries; document transport, storage and identity ownership with ADR alternatives and handoffs.

### Technology and licensing

- **Editor feasibility and technology selection**: Compare Excalidraw integration hooks, read-only guarantees, serialization and custom extensions; evaluate React/TypeScript/Fastify and MySQL/MariaDB; pin evaluated versions and compatibility limitations.

- **License and supply chain policy**: Review MIT compatibility of direct and transitive dependencies, fonts, icons and imported assets; record SPDX identifiers, attribution, distribution obligations and upgrade policy before adoption.

### Developer foundation

- **Monorepo build and engineering conventions**: Define frontend, API, bot and shared contract package boundaries; configure reproducible installs, lint, type checking, formatting and versioned builds; reject cross-layer imports.

- **Local environment and configuration validation**: Provide environment schema with PORT integer 1–65535, NODE_ENV development/test/production, DATABASE_URL mysql scheme, DISCORD_CLIENT_ID decimal string and SESSION_SECRET minimum 32 characters; report missing names without secret values; test valid, missing and malformed input.

### Governance and architecture continuity

- **Governance and contribution policy**: Define maintainers, review roles, decision escalation, contributor conduct and issue ownership; document Definition of Ready and Done; preserve unassigned backlog visibility.

- **ADRs, threat model and architecture checks**: Maintain versioned decisions with alternatives and evidence; trace requirements to interfaces, security controls and acceptance tests; detect undocumented boundary changes in PR review.

The requirements header describes a requirements and verification specification, not evidence of product operation. Objectives are defined as targets and are not measured.
- **T0.01 system boundaries:** [GB-T0.S1 system contract, revision 0.1](../specifications/GB-T0-S1-system-contract.md) (status: proposed, not accepted and not an implementation authorization). The quoted header is historical. The [delegated decision in PR #481](https://github.com/CompleteTech-DiscordApps/guildboard/pull/481#issuecomment-6919558260) is authoritative for current status: revision 0.1 is the accepted T0 system boundary contract. Downstream implementation and platform acceptance remain separate.
  - **Authority and scope.** A verified server session supplies identity, guild and channel context, session generation, and membership evidence. URL identifiers select objects within that verified guild. Resolve every board, object, and asset against the tenant and return the same public `NOT_FOUND` for unknown and foreign resources. Derive permission from current server policy, including action, ownership, mode, lock, role restrictions, and temporary grants. Apply expiry, revocation, and tenant checks on every command. Absent or stale required evidence denies privileged writes, and unenumerated actions are denied.
  - **Write fence.** A write transaction locks the scoped policy and board in the documented order, checks session and policy generations using trusted time, and serializes commit against revocation, invalidation, lock, and grant changes. The state change, revision, receipt, and accepted event commit atomically.
  - **Read delivery fence.** Serialize each protected transport release with session revocation, expiry, membership invalidation, and scoped read policy changes. At each release, use trusted time to check the current session, membership freshness, and scoped read policy. Apply the fence to live and replay events, snapshot metadata and chunks, receipts, ACKs, and receipt- or digest-dependent results including `IDEMPOTENCY_CONFLICT`. Denial reveals neither receipt existence nor digest match and leaves an unknown outcome unresolved. For asset and export metadata and each queued chunk, check scoped read authority for the board and every included asset. Direct storage access and pre-signed URLs cannot replace the fence. If an event that removes authority is ordered first, suppress that response and every later queued protected chunk. A release ordered first may complete. Withhold protected data and results if required evidence is missing or stale, or if the release boundary cannot enforce the fence. A denied ACK leaves the accepted commit durable.
  - **Bounded inputs and outcomes.** S1 specifies versioned logical command, receipt, event, and rejection shapes. Consumers must reject unknown fields or command kinds, bound encoded bytes before parsing, enforce per-command and queue limits, and return safe errors with explicit retryability. The initial proposed budget is 64 KiB encoded per command and 100 changes per compound. A timeout leaves the commit outcome unknown. Executable codecs, final budgets, and platform enforcement remain downstream adoption gates.

### Operator and contributor steps

Run from the repository root. These are the command forms found in the existing docs and workflows. None of them is a deployment step.

Offline, no network:

1. `python3 scripts/github-bootstrap/validate.py`: planning integrity. Run it before any planning change ([CONTRIBUTING.md](../../CONTRIBUTING.md)).
2. `python3 -m unittest discover -s tests/verification -v`: the T0 verification modules, including the checks for this section. The hardened local form adds `-I`: `python3 -I -m unittest discover -s tests/verification -v`.
3. `python3 scripts/verification/check_licenses.py`: the offline license gate, run locally as `python3 -I scripts/verification/check_licenses.py`. PASS is not legal clearance.
4. `python3 scripts/verification/verify_requirements.py` and `python3 scripts/verification/verify_architecture.py`: bounded definition and artifact checks ([planning workflow](../../.github/workflows/planning.yml)).
5. For ordinary boundary review, run `python3 scripts/architecture-controls/check.py --base /path/to/reviewed-base --current /path/to/proposed-tree` from the reviewed base tree, so the reviewed base supplies the policy. Use clean exports or separate checkouts before running Node builds, so generated workspace files do not change the inventory. For first installation only, when the checker is absent from the pinned base `8f75fdb398dfb48d577135ee08f295a4c4f634b6`, the [architecture-controls workflow](../../.github/workflows/architecture-controls.yml) runs the proposed checker with `--bootstrap-base-sha` and validates the pinned boundary witness. Follow the [controls README](../architecture-controls/README.md).
6. Gate tests: run `python3 -m unittest discover -s tests/architecture-controls -p 'test_*.py' -v` from the reviewed base for ordinary reviews and from the proposed tree only for the pinned first installation. Set `TMPDIR` to a writable scratch directory. The [architecture-controls workflow](../../.github/workflows/architecture-controls.yml) selects the test tree using the same rule as the checker.
7. Planning and research tests: `python -m unittest discover -s tests/planning -v` is the form the [planning workflow](../../.github/workflows/planning.yml) runs, where setup-python provides `python`. On a host with only `python3`, run `python3 -m unittest discover -s tests/planning -v` instead. Then run `python3 -m unittest discover -s tests/research -v`.

Remote or Node-based. Not executed by this handoff record:

8. `python3 scripts/github-bootstrap/audit.py`: read-only Project audit. It needs GitHub CLI authentication and network access.
9. With Node 24 and the committed lockfile, run `npm ci --ignore-scripts`, then `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run boundaries`, `npm run test:engineering`, `npm run build`, `npm run test:config` and `node scripts/verification/verify_engineering.mjs` ([engineering workflow](../../.github/workflows/engineering.yml)).
10. Run `npm run typecheck:config` and `npm run test:config`. The latter builds the package for `node scripts/verification/verify_config.mjs` and `node scripts/verification/verify_config_failure_paths.mjs` ([config workflow](../../.github/workflows/config.yml)).

The editor public-input fetch in the [editor workflow](../../.github/workflows/editor-acceptance.yml) needs network access and was not run here. For architecture-controls acceptance, use the [reviewed first-install tree and documented harness invocation](#gb-t00402v1--offline-architecture-controls-acceptance). Its revision argument is caller-supplied and the run needs a writable scratch directory.

Contributors claim work through maintainer coordination, use a focused branch, and reference the issue without closing directives until acceptance evidence exists ([CONTRIBUTING.md](../../CONTRIBUTING.md)). Negative tests for every authorization boundary and the evidence limitations belong in the PR. Security reports follow [SECURITY.md](../../SECURITY.md).

### Executable qualification

Run this block as a Bash script from a fresh, isolated Linux checkout of the exact candidate. The caller sets `GATE_REVISION` to the expected full SHA and `GATE_EVIDENCE_DIR` to a fresh directory outside the checkout on writable disk. The commands stop on failure and tee raw output to that directory. Review the reported results and skips before acceptance. The Git checks disable replacement objects, verify the original first-install tree ID, and treat executable-mode changes as dirty. Run the architecture checks before any Node build output exists.

```bash
set -euo pipefail
: "${GATE_REVISION:?set the expected full candidate SHA}"
: "${GATE_EVIDENCE_DIR:?set an absolute path outside the checkout}"
export GIT_NO_REPLACE_OBJECTS=1
test "$(git rev-parse --show-toplevel)" = "$PWD"
require_qualifying_checkout() {
  local worktree_status
  test "$(git rev-parse HEAD)" = "$GATE_REVISION"
  if ! git ls-files -v | LC_ALL=C awk 'substr($0, 1, 2) != "H " { masked = 1 } END { exit masked }'; then
    printf '%s\n' 'Use a fresh checkout without masked index entries.' >&2
    return 1
  fi
  worktree_status=$(
    git -c core.fileMode=true -c core.ignoreStat=false -c core.fsmonitor=false \
      -c core.trustctime=true -c core.checkStat=default \
      status --porcelain=v1 --untracked-files=all --ignored
  )
  test -z "$worktree_status"
}
require_qualifying_checkout
case "$GATE_EVIDENCE_DIR" in
  /*) ;;
  *) exit 1 ;;
esac
GATE_EVIDENCE_DIR=$(realpath -m -- "$GATE_EVIDENCE_DIR")
case "$GATE_EVIDENCE_DIR/" in
  "$PWD/"*) exit 1 ;;
esac
mkdir -- "$GATE_EVIDENCE_DIR"
(
  trap 'status=$?; set +x; printf "offline exit: %s\n" "$status"' EXIT
  set -x

  export TMPDIR="$GATE_EVIDENCE_DIR/scratch" PYTHONDONTWRITEBYTECODE=1
  unset EDITOR14_INPUTS
  first_install=8f75fdb398dfb48d577135ee08f295a4c4f634b6
  first_install_tree=673c4133ec499c90afc1d4c9d67ca405026c06ec
  test "$(git rev-parse "$first_install^{tree}")" = "$first_install_tree"
  first_tree="$GATE_EVIDENCE_DIR/first-install"
  installed_tree="$GATE_EVIDENCE_DIR/installed-policy"
  mkdir -- "$TMPDIR" "$first_tree" "$installed_tree"
  date -u '+%FT%TZ'
  git rev-parse HEAD "$first_install^{tree}"
  git version
  python3 --version
  node --version
  npm --version
  uname -sm
  findmnt -n -o FSTYPE -T "$TMPDIR"

  sha256sum docs/specifications/GB-T0-S1-system-contract.md \
    docs/specifications/fixtures/GB-T0-S1-scenarios.json

  git archive "$first_install" | tar -x -C "$first_tree"
  git archive 556dcf68a0d65c5e08fb4aeab2eaf0226f3c16a5 | tar -x -C "$installed_tree"
  python3 -B scripts/architecture-controls/check.py --base "$first_tree" --current "$installed_tree" --bootstrap-base-sha "$first_install"
  python3 -B scripts/verification/verify_architecture_controls.py --base "$first_tree" --installed "$installed_tree" --tmp "$TMPDIR" --revision "$GATE_REVISION" --exercise-evolved-candidate
  python3 -B -m unittest discover -s tests/architecture-controls -p 'test_*.py' -v
  python3 -B scripts/github-bootstrap/validate.py
  python3 -B -m unittest discover -s tests/planning -v
  python3 -B scripts/verification/verify_requirements.py
  python3 -I -B -m unittest discover -s tests/verification -v
  python3 -B -m unittest discover -s tests/research -v
  python3 -B -m unittest discover -s tests/research/editor13 -v
  python3 -B scripts/verification/verify_architecture.py
  python3 -I -B scripts/verification/check_licenses.py
  require_qualifying_checkout
) 2>&1 | tee "$GATE_EVIDENCE_DIR/offline.log"
```
