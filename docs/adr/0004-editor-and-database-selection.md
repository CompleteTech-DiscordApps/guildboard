# ADR 0004: Editor and database experiment selection

Status: section decision for a controlled experiment, 2026-11-16. Does not authorize installation or deployment. ADR 0001 and the accepted system contract govern.

Choose an Excalidraw 0.18.1 adapter in a React 19.1.0/TypeScript 5.9.3 Activity and a Fastify 5.6.1 API, with MySQL 8.4.7/InnoDB as the first database experiment. MariaDB 11.8.3 is the comparison and fallback candidate, not an interchangeable drop-in assumption. These are historical evaluation pins, not latest versions, security clearance or an adopted dependency lock. Refresh supported patch, security and license evidence before adoption. Node >=24 <25 is the existing repository engine constraint; Fastify 5's documented Node >=20 minimum alone does not prove compatibility with the whole dependency graph.

The adapter owns translation of tentative UI changes into versioned, bounded operation proposals and display of accepted server state. The server owns authenticated identity, guild and board authorization, current grants and permission epoch at every mutation and release, validation, transaction boundaries, sequencing, durable acknowledgment and recovery. It must fence revocation and in-flight writes; clients cannot authorize by asserting roles, upload arbitrary full scenes as authoritative state, or use full-scene last-write-wins. Storage owns atomic committed operations and their sequence/idempotency records; a failed transaction must not acknowledge a write. Presence and viewport are ephemeral. Exact schemas and concurrency semantics remain governed by the accepted contract; this decision does not change it.

MySQL's documented native JSON validation is useful for experimenting with bounded snapshots, but it cannot enforce tenant authorization or provide atomicity by itself. MariaDB documents JSON as a LONGTEXT alias with different semantics and replication implications. Both need explicit tenant keys, transactional constraints, private network, backup and tested restore. Do not infer SQL portability or atomicity from the names. Reconsider MariaDB or another database if measured transaction/recovery, operational, licensing or GoDaddy image constraints make MySQL unsuitable, after equivalent contract tests.

Trigger a narrowly maintained fork if supported hooks cannot express a required invariant after a browser experiment, with an upgrade and security maintenance plan. Consider custom canvas if the fork still cannot meet the contract or its maintenance burden is unacceptable; reproduce accessibility, editing and collaboration requirements. Never relax server authority to avoid these costs. See [comparison and evidence](../research/editor13/comparison.md).
